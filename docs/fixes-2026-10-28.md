# 引用、Windows 通知与界面修复（2026-10-28）

本次基于 yibanm/yunhu-richkobe 的 `f3ce8bb6fa81598b54e1d40863394613e1f31e47`，版本保持 1.0.5。检出时 master 与 desktop 指向同一提交；修复分支为 `fix/replies-notifications-navigation`。保留已经合入的 Toast、表情面板及聊天功能。

## 修改内容

| 问题 | 根因与修复 |
| --- | --- |
| 引用消息发送时报“请求参数错误” | 发送请求 SendMsgRequest 的引用 ID 是字段 8，历史消息 MsgData 的引用 ID 才是字段 9。之前把发送字段写成 9，与 Media 子消息冲突。现在修正发送字段，保留历史消息的读取字段，文字和媒体发送共用此修复。 |
| Windows Toast 无法使用 | windows-core 0.58 的 `PROPVARIANT::from(&str)` 生成 VT_BSTR，快捷方式的 System.AppUserModel.ID 要求 VT_LPWSTR。现在显式转换后写入，在创建窗口前注册应用身份，使用 WinRT 初始化；仅缓存成功注册，失败可以重试。前端显示准确初始化错误，异步失败带 HRESULT，测试通知可重新初始化。 |
| 引用跳转白框不消失 | locateId 原本一直保留到切会话或返回最新。现在点击目标消息以外、按 Escape 时立即清除定位状态和闪烁样式；点击目标本身保留高亮。捕获监听支持停止冒泡的按钮，并在卸载时移除。 |
| 侧栏账号与配置入口分散 | 合为“账号与配置”入口，固定在主题切换按钮上方；页面内用“账号与通知 / 应用配置”切换，保留原路径兼容，更多功能宫格不再重复列出两个入口。 |
| 已读群聊夹在未读前面 | 会话改为未读优先，同一阅读状态内再按置顶、时间排序。阅读、标记未读、实时推送会即时重排，各自定义分组内也使用相同顺序。免打扰仍保留自己的通知规则。 |
| 已读、未读难以区分 | 未读名称使用强调色和更粗字重，摘要、时间取消淡化；已读保留次级文字色。免打扰的未读会话也保留文字区分。 |
| HTML 消息紫底暗字看不清 | 净化后移除作者强制设置的文字色、背景、透明度和相关混合效果，保留文字内容、链接、图片、排版、间距与圆角。HTML 与 Markdown 内嵌 HTML 跟随主题，链接使用可读链接色和下划线。修复己方气泡链接硬编码浅色的问题。消息原文不变，原有净化仍执行。 |

协议核对来源：yh-Tpdev/yhchatAPI 的 `4c7e5288b14787b2c6cdd15a30b45a8e9b9af3d0/src/full.proto`，分别查看 SendMsgRequest 和 ListMsgResponse.MsgData。

## 使用与构建

源码包包含完整源码及此次构建的 `dist`。Web 可使用新 dist；Windows Toast 修改涉及 Rust 原生程序，必须重新打包客户端，不能只替换前端文件。

在 Windows 项目根目录执行（已具备项目要求的 Node、Rust 和 Tauri Windows 构建环境）：

```powershell
npm ci
npm run typecheck
npm run test:chat
npm run build
node scripts/build-server-bundle.mjs
New-Item -ItemType Directory -Force src-tauri/resources/dist | Out-Null
Copy-Item dist/* src-tauri/resources/dist -Recurse -Force
Copy-Item (Get-Command node.exe).Source src-tauri/resources/node.exe -Force
Push-Location src-tauri
npx tauri build --bundles nsis
Pop-Location
```

安装器位于 `src-tauri/target/release/bundle/nsis`。本次没有生成 Windows 安装器，也没有发布或覆盖 GitHub Release。GitHub 连接读取返回账号停用 403，未推送远端。

安装后从主题切换按钮上方进入“账号与配置 → 账号与通知 → 消息通知”，选择 Windows 系统通知并发送测试通知；若系统返回失败，页面会显示具体错误，可重试。系统免打扰和应用通知开关仍由 Windows 管理。
