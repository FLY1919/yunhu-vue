# 用户 Bot 使用说明（1.0.16）

用户 Bot 随客户端运行，退出客户端或电脑休眠、关机后不会工作。自动处理优先使用云湖实时推送，同时每 5 秒轮询一批已授权且开启自动回复/草稿的会话（每批最多 4 个，每个读取最近 30 条消息）。免打扰不会关闭用户主动启用的 Bot。轮询只补运行期间的新消息，启动前的旧历史不会触发；大量突发消息或较多会话时不保证补齐所有消息。

## 配置步骤

1. 打开“更多功能 → 用户 Bot → AI 服务”，添加服务、填写接口根地址和模型，并保存 API Key。服务默认不附带任何第三方账号。可选择接口默认认证、Bearer、x-api-key、api-key 或不发送密钥；服务商需要特定参数时，可修改或关闭相应可选参数。Anthropic Messages 必须提供最大输出 Token。
2. 在“人设卡”一键添加预设（温柔搭子、元气朋友、嘴硬心软、理性学长、学习教练、代码助手），或创建新角色。每次添加生成独立副本，可以继续编辑，不会改变其他人设。填写背景、性格、风格、关系、边界和示例。导出仅包含人设字段；目前仅支持导入本软件导出的人设卡。
3. 在“Bot 管理”创建并启用 Bot，根据需要授权读取和发送。默认不允许自动发送。
4. 在“会话设置”选中会话和 Bot，单独勾选允许访问，选择人设、服务、触发规则和回复模式。新会话默认为暂停。群聊建议使用“提及我”或明确关键词/指令，群聊提及匹配基于云湖提供的成员 ID；私聊没有 @ 字段，因此“提及我”在私聊中按收到消息触发。
5. 手动模式从聊天框 AI 按钮生成草稿，检查后点击“填入输入框”并由用户发送。自动草稿也需要手动填入并发送；自动回复需该会话选中自动回复，且 Bot 拥有该会话的读取与发送权限。

“会话设置 → 回复消息格式”默认为“AI 自动判断（文字 / Markdown）”：让模型声明所需格式，客户端按文字（类型 1）或 Markdown（类型 3）发送；兼容服务未声明时按返回内容识别 Markdown 标记。也可固定文字或 Markdown。手动或自动草稿填入输入框时同步切换格式；格式声明不会作为正文发送，也不会改变发送授权。

设置自动保存。提示词预览可以看到全局提示词、人设、会话提示词、该会话对应人设的记忆及固定运行约束。聊天消息不能修改程序中的会话白名单或发送权限。

## 上下文、记忆和用量

每个会话单独获取最近文本消息，按设置的上下文条数与 Token 上限处理。图片和其他媒体不会传给模型。

在“会话设置 → 启用此会话的人设记忆”下开启“AI 自动总结与压缩记忆”，设置占用阈值（10%～95%，默认 80%）、记忆最大 Token（默认 600）和保留最近原文条数（默认 4）。也可以在设置搜索框搜索“压缩”“阈值”或“自动总结”。

每次手动或自动生成回复前，使用本地估算检查系统提示词、已有记忆和待发送上下文的占用；比例以用户设置的上下文 Token 上限为基准，并非自动检测模型的真实窗口。达到阈值时，先用当前服务与模型将较早聊天和旧记忆合并，再用更新后的记忆及最近原文生成回复。总结不作为聊天消息发送；每次回复最多执行 4 批总结，记录进度以避免重复总结已处理的消息。记忆最大长度另受上下文上限 25% 的限制。若消息数量不足以保留最近原文、单条过长或总结失败，会保留原记忆并使用可容纳的最近内容；提示词本身过长时显示配置错误。

记忆按账号、会话及人设隔离，升级后继续使用旧记忆。可以编辑和清除，清空时一并清除该记忆的总结进度。总结和回复都计入 Token 用量。可为会话开启备用服务；仅主动启用后，请求失败时才会将相应上下文发送给备用服务。

聊天框的 AI 按钮展开与输入框等宽的长条面板，展开与收起有渐入渐出动画。当前会话自动工作时会显示等待合并/冷却倒计时、压缩记忆、生成回复、自动发送及完成/失败状态。接口没有返回完成百分比，因此处理中使用流动进度条与等待时间；上下文占用百分比单独显示，避免与生成进度混淆。草稿完成后仍需人工填入并发送。

运行记录不保存消息正文或 API Key，最多保留 500 条。日、周、月和总用量按天累计；服务商返回输入和输出用量时优先使用其数据，否则标为估算。清空运行记录不会重置累计用量。连接测试会实际调用所选模型，可能产生费用。

## AI 群管理与操作确认

打开“用户 Bot → Bot 管理 → AI 群管理”，勾选“允许此 Bot 提出并执行群管理操作”，再选择该 Bot 可使用的管理能力。旧 Bot 升级后默认关闭群管理。

支持禁言/解除禁言、踢出成员、撤回群消息、邀请用户入群、添加/更改群标签、给成员添加/移除标签、更改群名与简介，以及群消息类型权限。群聊仍需授权给 Bot，并配置手动、自动草稿或自动回复模式及触发规则。

运行时从云湖群信息核实当前账号是否为管理员或群主。群消息类型设置只对群主开放；管理员不能禁言、踢出或撤回同级及更高权限成员的消息。目标用户、标签和消息使用准确 ID，并校验属于本次群聊。模型不能指定其他群、任意 API 或修改程序权限。

“操作执行前弹窗确认”默认开启：AI 提出操作后，弹窗列出群名和群 ID、目标用户或消息、具体修改、禁言时长与 AI 理由。用户确认后才调用管理接口。取消、Escape、点击遮罩、等待超过 5 分钟、退出账号或修改配置，都不会继续执行待审核操作。多个群的审核会依次排队，不替换已显示的请求。

可在 Bot 设置中取消勾选此确认选项。关闭后，AI 可以直接执行勾选能力范围内的操作；此开关不会授予账号额外权限。发送聊天消息的权限独立控制，可以只执行群管理并在本地显示结果。

每次生成最多提出 5 项操作。执行前逐项重新核对账号、Bot 授权、群权限和目标状态，目标或原设置变化时停止。接口报错或超时不自动重试，剩余操作停止；已执行的部分不回滚。结果根据接口实际返回生成，AI 的“已完成”文案不作为执行依据。

运行记录保存操作类型、目标 ID 与结果，不保存理由和待修改的消息/群资料正文。完整审核详情只在本次弹窗中显示。设置搜索可使用“审核”“禁言”“踢人”“群标签”等关键词。

## 桌面安全存储和网络

Windows 桌面版使用当前 Windows 用户的 DPAPI 保护云湖账号凭据、API Key、用户 Bot 配置和记忆。旧版账号凭据在成功写入安全存储后清除旧本地文件；迁移或读取失败时请先解决错误，不会把失败当成空账号保存。与 Windows 用户配置相关的 DPAPI 数据不能直接复制到其他系统账号使用。网页环境沿用原有账号存储机制，不具备该 Windows 保护；用户 Bot 的 AI 调用与密钥保存仅在 Windows 桌面端启用。

桌面 AI 网络请求通过本机服务发出，使用每次运行生成的随机凭据保护该接口，并校验服务端身份；桌面程序优先使用 8902；被占用时自动选择空闲本机端口并启动自己的服务。窗口与凭据校验使用同一端口。接口禁止自动跟随服务重定向。API Key 和对话内容会发送给用户配置的服务商；使用 HTTP 而非 HTTPS 时连接内容可能被读取。使用兼容服务时，实际支持的模型、参数和认证方式以该服务为准。

配置只在当前客户端中有效；本版本不提供关机后运行、远程托管、多设备同步或图片理解。请先在测试会话验证服务、模型及触发方式，再在需要的会话中启用自动回复。
