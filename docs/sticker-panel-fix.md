# 大量表情包下的面板修复（2026-10-26）

## 原因与行为

原面板把“收藏 + 所有表情包”放在图片区上方的自动换行分类栏中。分类数量增长时，分类栏不断占用弹层高度，图片区会被挤到下方。未收藏合集也位于独立滚动区外，内容较多时可能无法完整查看。

`src/components/StickerPanel.vue` 现在采用受视口高度约束的弹层：

- 桌面左侧为分类栏，右侧为当前分类的表情内容。左右分别滚动，所有中间容器允许收缩，分类数量不会增加弹层高度。
- 左侧支持按表情包名称或 ID 搜索。右侧单独支持按表情名称、文件名或 ID 搜索；兼容全角字符和大小写。
- 窄于 620px 时用分类下拉框替代侧栏，搜索与当前内容仍保留。
- 未收藏合集直接占用右侧图片区，不再在正常列表上方另堆一整块图片。提供“添加该合集”和“返回我的表情”，浏览时阻止误上传到其他分类。
- 分类名称最多显示两行，完整名称可悬停查看；显示当前分类与数量。图片使用懒加载与异步解码，快捷回复区有高度上限并自行滚动。
- 从聊天消息打开表情时，清理遮挡目标的搜索条件，并只在图片区内定位高亮。修正个人收藏 `fav` 被错误转换为数字后无法高亮的问题，兼容数字/字符串合集 ID。
- 切换分类时清理旧菜单和重命名状态。面板关闭或卸载时移除粘贴及延迟注册的菜单监听器，保留正常上传、发送、收藏、置顶、删除和重命名入口。

## 验证

`npm run test:chat` 共 46 项通过，其中新增 6 项直接挂载真实 `StickerPanel.vue` 的 setup，验证：

1. 初始关闭的面板安全挂载，关闭后清理尚未注册的右键菜单监听。
2. 模拟 120 个合集、每包 200 张表情；分类搜索与表情搜索互不干扰，数字/字符串 ID 兼容。
3. 手动切分类后退出未收藏浏览，清理旧搜索、菜单和重命名状态。
4. 外部定位清理过滤条件，个人收藏和未收藏合集都能找到对应表情。
5. 用模拟 DOM 几何验证定位仅滚动图片区，并使用区域自身的滚动偏移。
6. 粘贴上传指向当前分类，未收藏合集阻止上传，关闭/卸载后不再处理粘贴。

同时通过类型检查、源码预检、Vite 生产构建、Node sidecar 打包与 `git diff --check`。未进行浏览器像素布局或 Windows 实机验收；上述离线测试不等同于真实浏览器排版验证。

建议实机分别在 1100×760、720×480、390×640 和矮窗口中检查深浅色：左右滚动、名称/ID 搜索、下拉分类、快捷回复数量较多时的高度、未收藏合集底部访问及聊天表情定位。
